# 雨水下水道開孔抽樣巡檢覆蓋率

以人孔開孔紀錄推算下水道管線的實際巡檢覆蓋長度，並以互動地圖呈現。
純靜態網站，放上 GitHub Pages 即可使用，手機可直接操作。

---

## 這套系統在算什麼

開孔是抽樣巡檢：開一座人孔，代表巡檢了它與上下游鄰孔之間**各一半**的管線。

| 情況 | 計算方式 |
|---|---|
| 管段兩端都是人孔 | 各自負責一半長度 |
| 只有一端有人孔（末端、或另一端分岔於無人孔的轉折點） | 該人孔負責**整段** |
| 兩端都沒有可開孔人孔 | 無論如何都巡不到，計為未巡檢 |

**關鍵處理**：圖資中的「虛人孔」是管線轉折點，不是真實人孔。
若直接當成受檢端點，覆蓋率會嚴重高估。建置時會自動穿越合併度數為 2 的轉折點，
讓每條邏輯管段的兩端必為真實人孔或真正的端點／分岔。

所有受檢單元的長度總和**等於管線圖資總長**（守恆誤差 < 0.3 公尺，純浮點捨入），
確保不重複計算、不遺漏。

## 功能

- **三種著色模式**：巡檢狀態、巡檢次數、巡檢月份
- **月份模式**可切換
  - 單月：該月實際巡檢的管段
  - 累積：1 月到指定月份的累積成果，依**首次巡檢月份**上色，同段重複巡檢不重複累加
  - 自動播放，看整年巡檢如何在市區推進
- **篩選**：年度、行政區（多選）、巡檢狀態、巡檢次數、最短管段長度
- **待補缺口清單**：最長的未巡檢管段，或依「離我最近」排序供現場人員使用
- **定位**：現場開啟即可看自己站在哪、附近哪些管段還沒巡
- **行政區界**：選取行政區時以淡色虛線框出範圍，地圖自動縮放到整個區界都看得見
- **浮動資訊視窗**：選區後顯示該區摘要，可拖曳、縮放、收合、關閉；
  內容採固定字級加彈性容器，縮到最小尺寸也不會跑版（改以捲動呈現）
- 單指拖曳、雙指縮放、可點擊的縮放條；手機為三段式底部面板，桌機自動變左側欄

未巡檢在地圖上刻意分成兩種顏色，因為它們是兩件不同的事：

- 🔴 **列管人孔未開孔** — 有孔沒開，排進計畫就能補
- 🔵 **管段兩端無人孔** — 根本沒孔可開，要增設人孔或改用其他檢測方式

把後者當成巡檢績效不足來檢討，會錯估問題。

```bash
git clone <你的 repo>
cd <repo>
# 直接把整個資料夾內容 push 上去
git add . && git commit -m "init" && git push
```

到 GitHub 的 **Settings → Pages**，Source 選 `Deploy from a branch`，
分支選 `main`、資料夾選 `/ (root)`，存檔後約一分鐘即可從
`https://<帳號>.github.io/<repo>/` 開啟。

本機預覽（不能用檔案總管直接雙擊 `index.html`，瀏覽器會擋住讀取 JSON）：

雙擊就能開（只有底圖需要網路）。

## 擴充：新增月份、年度或新版圖資

資料與程式完全分離，**不需要改任何程式碼**。

> `source/` 不納入版本控制（管線 `.dbf` 超過 GitHub 單檔 100 MB 硬限制）。
> 重新建置前，先把原始圖資與 Excel 放回 `source/`，詳見該資料夾的說明。

### 新增月份（例如 10～12 月的紀錄進來了）

1. 用新的 Excel 覆蓋 `source/` 裡的檔案（維持兩個工作表：列管清單、開孔紀錄）
2. 重新建置：

```bash
pip install -r tools/requirements.txt   # 第一次才需要
python tools/build.py --inline
```

月份控制列會自動長出新的月份，不必改設定。

### 新增年度（例如 116 年度）

1. 把 116 年度的 Excel 放進 `source/`
2. 在 `tools/config.json` 的 `years` 陣列加一筆：

```json
{
  "id": "116",
  "label": "116 年度",
  "ad_year": 2027,
  "network": "net-20260915",
  "workbook": "source/116年度列管人孔開孔狀態統計.xlsx",
  "listed_sheet": 0,
  "record_sheet": 1
}
```

3. `python tools/build.py --inline`

年度選單會自動出現 116 年度，切換時只重新載入約 100 KB 的年度檔，
管網幾何（約 1.7 MB）沿用同一份、不重複下載。

### 換成別的縣市或更新行政區界

`data/boundaries/tainan.json` 的格式很單純，`areas` 以**區名**為鍵，
值是一組外環座標 `[[lng, lat], …]`（一個區可以有多個環，離島或飛地用得到）：

```json
{ "label": "臺南市行政區界", "areas": { "歸仁區": [[[120.29,22.86], …]] } }
```

只要區名與管線圖資的 `行政區` 欄位一致就會自動對上。
換檔案後在 `tools/config.json` 的 `boundaries` 指向新路徑即可；
不放這個檔案也不影響其他功能，只是地圖不畫區界。

### 換成新版管線圖資

在 `config.json` 的 `networks` 加一筆新的 id（例如 `net-20270315`），
指向新的 shapefile，再讓該年度的 `network` 指向它即可。
**舊年度仍指向舊圖資**，歷年數字不會因為圖資更新而被追溯修改。

### 欄位不一樣怎麼辦

建置程式以關鍵字比對欄位（行政區、人孔／NUM／編號、日期），
欄位名稱小幅變動不會壞掉。若 Excel 結構差異較大，
調整 `tools/build.py` 的 `norm_cols()` 關鍵字即可。

## 目錄結構

```
├── index.html                 頁面骨架
├── standalone.html            離線單檔版（build.py --inline 產生）
├── assets/
│   ├── app.js                 前端程式：載入、著色、篩選、統計、互動
│   └── styles.css             樣式（手機優先，900px 以上切換為側欄）
├── vendor/leaflet/            Leaflet 1.9.4（不依賴外部 CDN，內網也能用）
├── data/
│   ├── manifest.json          年度與圖資清單，前端的進入點
│   ├── network/*.json         管網幾何與拓樸（約 1.7 MB，多年度共用）
│   ├── years/*.json           各年度開孔結果（約 100 KB）
│   └── boundaries/*.json      行政區界（約 138 KB，已簡化至約 25 公尺精度）
├── tools/
│   ├── build.py               資料建置管線
│   ├── config.json            資料來源設定（新增年度只改這裡）
│   └── requirements.txt
└── source/                    原始 Excel 與 shapefile（不入庫，見該資料夾說明）
```

### 資料格式

`data/network/*.json` 以欄式陣列儲存，索引即單元 id：

| 欄位 | 說明 |
|---|---|
| `d` | 行政區索引（對應 `dists`） |
| `len` | 長度（公尺） |
| `node` | 負責這段的受檢人孔編號 |
| `blocked` | 0＝可巡檢；1＝兩端無人孔；2＝端點編號缺漏 |
| `geom` | `[[lng, lat], …]` WGS84 |

`data/years/*.json` 與上面**同索引對齊**：

| 欄位 | 說明 |
|---|---|
| `m` | 月份位元遮罩，第 n 位為 1 代表第 n+1 月有開孔 |
| `cnt` | 該年度開孔次數 |
| `listed` | 該人孔當年是否列管 |

用位元遮罩存月份，12 個月只要一個整數，年度檔因此只有約 100 KB，
手機切換年度幾乎無延遲。

## 已知的資料議題

建置時會一併印出，也反映在地圖的顏色分類上：

- **虛人孔比例偏高的行政區**（例如新市區 84%）覆蓋率偏低，
  主要反映圖資結構而非巡檢不足，檢討前請先確認
- **端點編號缺漏**：部分管段端點編號（形如 `67-2224256-001`）不在人孔圖層中，
  建置時會用 1 公尺容差的座標吸附救回大部分，仍有少數無法對應
- **孤立人孔**：部分已開孔人孔在管線圖層中沒有連接管線，其成果無法換算成管線長度
